# Cutroom

你在这个文件夹里剪片，对方在 Cutroom 页面上看片、在时间轴上指出位置、写评论。两边靠**交接**往返：你交出一个版本，对方把评论发回来。交接只有一个命令，`cutroom review`。

## 开工

对方要做一个新视频时，项目由你搭好，对方只需要说素材在哪、想要什么样的片子。

1. **定文件夹。** 当前目录是空的，或者已经是这个片子的项目，就用当前目录；否则在当前目录下按片子的名字新建一个子文件夹，后面都在里面做。
2. **收素材。** 把对方给的文件或文件夹拷进 `media/user/`，保留原文件名。单个文件很大时改用软链，并告诉对方原文件不能移动。对方没给素材、或者说要你找时，搜索下载到 `media/fetched/`。
3. **建索引。** 逐个看素材（时长、画面、有没有人声），写进 `assets.json`。同一镜头的不同素材用同一个 `group`。
4. **问清楚。** 片长、横竖版、成片风格这些需求没说清的，一次问完，再开始剪第一版。

git 仓库和 `review/` 由第一次 `cutroom review` 自动建好。

## 每一轮

1. **剪。** 改 `assets.json`、`timeline.json` 和需要的素材，渲染到 `renders/vN.mp4`。N 是下一个版本号：`git log --format=%s` 里最大的 `vN:` 加一，还没有版本时是 `v1`。写这些文件前读 [format.md](format.md)。版本由命令提交，你不用 `git commit`。
2. **预检。** 自己看一遍新渲染：手指或人脸变形、物体闪烁或消失、画面文字乱码、前后镜头服装场景不一致、色调跳变、音画不同步。每个疑点写成一项发现，存成一个 JSON 数组文件（格式见 format.md）。没有疑点就不传。
3. **交接。** 在后台运行（Bash 的 `run_in_background`）：

   ```bash
   cutroom review -m "这一版一句话摘要" --replies /tmp/replies.json --findings /tmp/findings.json
   ```

   命令先提交新版本，再打开审片页，然后阻塞等待。把它在 stderr 打出的地址告诉对方，然后停下，等命令结束的通知。上一版没有发来评论时不传 `--replies`。

4. **读评论。** 命令结束时 stdout 是一个 JSON：`comments` 是这一版的全部评论，`verdicts` 是对方对你上一轮回复的判断（`closed` 接受，`reopened` 不满意，那条已经作为带 `reopens` 的新评论出现）。逐条读，需要时打开 `context.frame` 的截图。
5. **改。** 直接动手。评论有歧义、互相冲突、或者要动之前说过要保留的部分时，先在对话里问清楚再改。每条评论都写一项回复，存进回复文件：

   ```json
   [{ "comment": "c-07", "text": "裁掉了 3 帧穿帮", "done": true }]
   ```

   没做的写 `done: false`，`text` 写原因。命令会拒绝漏掉评论的交接，并列出缺了哪几条。然后回到第 1 步。

对方说“看评论”，或者你不确定有没有新评论时，运行不带参数的 `cutroom review`：评论已经发来就立刻返回，否则开始等待。命令被拒绝时，stderr 写着原因，照着改了再运行。

## 评论

- 时间都是秒，从成片开头算。`region` 是相对画面的比例，左上角为原点。
- `anchor.kind`：`point` 时间点，`range` 时间段，`clip` 片段，`seam` 两个片段之间的接缝，`region` 画面区域，`track` 整条轨道，`global` 全片。
- 评论没有分类，读懂这句话想要什么：指出问题由你决定怎么修；描述节奏或情绪的感受，你把它落成具体动作，并在回复里写明做了什么；只是提问就只回答、不改动。
- 说某处很好、要保留的，之后任何一轮都不要动它，除非对方明确撤回。
- `finding` 表示你某条预检发现被对方确认成了问题。

## AIGC 素材穿帮

这里不接生成模型，只能在已有素材里规避。按代价从低到高试，并在回复里写明用了哪种：

1. 裁掉穿帮的几帧。
2. 换成同组（`group` 相同）的其他素材。
3. 放大裁切画面，或用字幕、贴纸遮住。
4. 都不行时说明这个镜头需要补素材，`done: false`。

## 边界

- 只用已有素材和代码生成的素材。生成或重新生成视频、数字人、文字转语音不在这里做。
- 第一版做横版 16:9。导出前先问对方要 1080p 还是 4K。
- 搜索下载的素材放进 `media/fetched/`，在索引里写明出处和授权。
